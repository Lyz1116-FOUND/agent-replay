# 本片制作提示词

使用 onetake 的制作协议与 motion.js，制作 Agent Replay 的 24 秒产品短片。

画面概念：一只蓝色小机器人就是鼠标。桌面上的输入、点击、拖动、回放，都由它亲手引发。角色不是旁观吉祥物：手接触进度条后才发生拖动，按下回放后才展开历史结果。观众要先看懂它在做什么，再看到界面的反应。

美术：暖白桌面、产品蓝、深蓝文字。Three.js 中建立真正有厚度的圆角窗口和机器人，使用柔和侧光、接触阴影、少量景深。角色造型属于本项目，不复制 Clawd。Blender 可用于后续细化模型；没有 Blender 时明确使用程序化建模，不声称已有 Blender 资产。

故事：不要停在 Done。机器人输入 Replay the last run 并点击；输入条长成工作台；出现 8 failed；机器人后退半步并静止思考；抓住现有时间线往回拖；镜头提前半拍落在历史 EDIT 上；放大比较条件，再看到 popitem(last=True) → popitem(last=False)；机器人按下回放；历史测试结果显示 14 passed；拉远进入真实产品演示；机器人拖动窗口，让它收成播放按钮；落定 AGENT REPLAY 和演示地址。

运镜：一台连续相机。远景留白，角色反应给近景，拖动时跟随，阅读代码时完全停止，结尾保留至少两秒静止。不要让每段动作等长。每一个分段必须写明从上一段留下来的对象。开头输入条、工作台、代码容器、产品窗口、结尾按钮是一条连续物体变化链。

节奏：点击、抓住、放开、测试落地、窗口收拢落在相同音乐网格上；声音先服务于动作因果。只用一套木质点击、空气拖动、低频落地与柔和和弦，置于同一短混响空间。阅读停顿要在画面和声音上都留白。不堆叠蜂鸣音，不加粒子礼花。

事实：LRU 是已有 built-in demo 的重建；8 failed 与 14 passed 是历史演示记录，不是本次运行的新测试。产品是回放调试器，不演成自动修复工具。真实产品素材须标注录制来源。

角色表演：眼睛要有视线、眼睑开合、眼形变化和高光；表情从好奇转为吃惊、怀疑、专注、思考、发现线索、开心、邀请。眉毛和嘴形只辅助眼睛。动作前有预备，点击有压缩，拖动有身体倾斜，落地有回弹，触角有滞后；通过时弯眼笑并做两次高低不同的跳跃，结尾挥手后停下来。用一段较近的角色反应镜头，让表情真正读得出来。

工程：每个状态必须是时间的纯函数，提供 __seek / __ready / __track / __meta。先出关键帧检查，再出成片；本轮使用 1080p60、8–16 次线性光 180° 快门采样，静止不要糊。验证角色完整入画、乱序 seek 一致、音频无削波、节奏有静止、对象有连续承接。检查未通过就修订，不把验收工具输出包装成主观审美保证。

参考限制：目前只取得用户贴出的提示词和 onetake 仓库，未取得 Clawd 原视频直接链接。不能宣称已逐帧分析该视频，也不能杜撰它的 BPM、镜头或静止比例。

发布版追加要求：每段只保留一个主要视觉焦点，代码阅读时弱化周边上下文。让转场从回车箭头中心、时间线游标、False 的下划线、测试结果底部细线和窗口边缘小点开始；它们要持续存在，并有可见的形变或位移。片尾先让角色带回播放按钮，再出现大标题，避免字幕和动作争夺注意力。
